S3 est une API HTTP avant d'être un produit : des **objets** (un blob et ses métadonnées)
rangés dans des **buckets**, adressés par une **clé**, signés par une paire de clés d'accès.
AWS l'a inventée, tout le monde l'a copiée. Un code qui ne parle que cette API change de
serveur en changeant quatre variables d'environnement.

## Le modèle mental

Chaque serveur S3 a deux faces :

| | Plan de données | Plan de contrôle |
| --- | --- | --- |
| Ce que c'est | l'API S3 : `PutObject`, `GetObject`, `ListObjectsV2`, URL pré-signées, CORS | créer des buckets et des clés, donner des droits, gérer le cluster |
| Commun à tous ? | **oui**, à quelques trous près | **non**, propre à chaque serveur |
| Outils | SDK AWS, `aws` CLI, `rclone` | `garage` CLI, `mc admin`, console RustFS, IAM chez AWS |

L'application ne touche que le plan de données. Changer d'outil, c'est réapprendre le plan de
contrôle — d'où une page par serveur, et le reste en commun.

## Choisir un serveur

| | Garage | MinIO | RustFS | AWS S3 |
| --- | --- | --- | --- | --- |
| Licence | AGPLv3 | AGPLv3 (communautaire), AIStor (commercial) | Apache 2.0 | service managé |
| Langage | Rust | Go | Rust | — |
| État | maintenu (Deuxfleurs, France) | communautaire **archivé** en 2026, plus de binaires ni d'images | jeune, 1.0 en 2026 | — |
| Cible | petits clusters géo-distribués, matériel hétérogène | gros volumes, performance | remplaçant de MinIO | tout |
| Console web | non (CLI + API d'admin) | oui (réduite dans la version communautaire) | oui | oui |
| Chiffrement au repos | SSE-C seulement | SSE-S3 / SSE-KMS (avec KMS) | SSE-S3 / SSE-KMS (avec KMS) | SSE-S3 par défaut |
| Config | fichier TOML + layout de cluster | variables d'environnement | variables d'environnement | IAM |

Garage est le choix par défaut pour de l'auto-hébergement sur un ou quelques serveurs.
MinIO se rencontre encore partout, mais en installations existantes.
