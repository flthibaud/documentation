## Le tableau de choix

Quand on hésite, c'est presque toujours entre ces six-là.

| Besoin principal | Structure | Coût typique |
| --- | --- | --- |
| Accès par position | Tableau dynamique | O(1) |
| Recherche par clé | Table de hachage | O(1) en moyenne |
| Garder les éléments triés | Arbre binaire de recherche équilibré | O(log n) |
| Toujours le plus petit / grand | Tas binaire | O(log n) pour extraire |
| Traiter dans l'ordre d'arrivée | File | O(1) |
| Défaire la dernière action | Pile | O(1) |
| Relations entre entités | Graphe | dépend du parcours |

## Critères de choix

1. **Opération dominante** — c'est elle qui doit être rapide, le reste peut coûter.
2. **Volume** — sous quelques centaines d'éléments, un tableau bat souvent une structure
   plus savante : moins d'indirections, meilleure localité mémoire.
3. **Ordre nécessaire ?** — si oui, la table de hachage est éliminée.

La complexité asymptotique ignore les constantes et le cache CPU : un tableau parcouru
linéairement peut battre une liste chaînée théoriquement équivalente d'un facteur dix.
